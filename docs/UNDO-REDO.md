# Undo / Redo Notes
* undo/redo history itself doesn't persist across save/load — it's a session-only feature, which matches how most CAD tools behave anyway, not a real limitation.
* The whole Position session is committed as one transaction at Done: Back keeps its existing fine-grained in-dialog stepping, and the undo history reads the way a CoCreate user expects — one entry per completed placement, Ctrl+Z undoes the whole positioning as a unit.
* workplanes and sketch state live outside the OCAF document, so undo won't restore them.
* Undo (Ctrl+Z) and Redo (Ctrl+Y) are guarded — "Nothing to undo" in the status bar rather than a dead click — and after each undo/redo the status line reports how many of each remain.
* Every mutating gesture is now a transaction: extrude, the five modify operations, STEP import, delete, rename, create assembly, shared instance, and drag-reparent — thirteen call sites total across kodacad.py and mainwindow.py, each wrapped in a small contextmanager that commits on success and aborts on exception. After an undo, the app does the full reset: active-part state cleared (cached uids can dangle when labels are recreated), reparse, rebuild tree, redraw.
* In the Position dialog, the whole Position session opens one transaction at dialog start and commits at Done (or on close via X, preserving what's on screen — an empty command commits to nothing). Back keeps its fine-grained stepping unchanged, inside the open transaction. The piece that made this clean: the transaction contextmanager joins an already-open command instead of nesting, so the dialog's internal moves pass through the same wrapper as standalone repositioning with zero special-casing.
* Two scope notes, both logged and in the checklist: session load correctly clears undo history (the doc object is replaced; the fresh one gets its undo limit re-set), and workplanes/2D sketch state live outside the OCAF document, so undo doesn't touch them.
